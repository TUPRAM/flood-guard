# outputs/planning_v1

Small committed outputs of the planning overlay (restructuring plan v2, section 3.1). On 3 October 2026 this folder holds only the receipts of the engineering runs made for protocol v1b. Protocol v1b is **not signed**: no FPPS, no A–E class and no ensemble has been computed, and no file here holds a value for a single tambon.

**Every file** carries `generated_at_utc`, `source_timestamp`, `confidence_class` (always `low`), `confidence_basis`, `assumptions`, `official_warning: false` and `operational_status: non_operational`. In a JSON file they are at the top level; in a GeoJSON file they are in the feature's properties. A candidate file also carries `status: candidate` inside the file, so a copy taken out of this folder still says what it is. `tests/test_planning_v1_outputs.py` checks all of this for every file here. None of these outputs is an official warning or an observation of a flood.

Each spike file carries its generation time, so its SHA-256 changes from run to run. To compare two runs, use the hashes of the content alone: `geometry_sha256` in a corridor file, `joins_sha256` in a join log and `context.canonical_sha256` in a spike receipt. The `reproducibility` block of a spike receipt does that comparison against the run before it.

The inputs are read-only files outside Git. Their locations are arguments of each script, and their SHA-256 values are in each receipt. The owner decisions these candidates wait on are in `docs/proposal_execution/planning_protocol_v1b_owner_choices.md`.
