# Bilingual candidate case briefs

Status: **PASS for the eight source-bound candidate HTML/PDF briefs; broader release checks remain separate.** These are research case briefs for the competition profile, generated from EvidenceLibrary package version `3385c9eacccd0d2d`. They do not establish an accepted observation, FPPS, A-E class, affected population, age equity, verified shelter capacity, current road condition or official warning. Public-production exclusion, exact Preview alignment and second-machine rehearsal require their own release receipts.

## Source and export boundary

`apps/web/scripts/build-case-briefs.mjs` reads only the allowlisted Public projection catalog for brief content. It verifies the caller-pinned projection catalog SHA-256, every projection SHA-256, the source EvidenceLibrary catalog SHA-256, every referenced source package SHA-256, case/AOI/event/version identity, candidate/null decision fields, finite nonnegative access values, and the explicit public-derivative flags for WorldPop, OSM, reporting boundaries and scenario inputs. A case with a candidate flood scenario also requires the SAR candidate public-derivative flag. The generator does not copy source geometry, image layers, raw rows, personal contacts or restricted dataset text into the briefs. Output HTML has no remote fetch and embeds the bundled Noto Sans Thai font; PDF is printed from the same HTML.

The manifest at `apps/web/public/briefs/catalog.json` has schema `floodguard.case_briefs.v1`. It lists exactly eight case IDs, each with HTML/PDF URLs and SHA-256 values, source projection/package SHA-256 values, and the pinned projection and EvidenceLibrary catalog SHA-256 values. The exported file set is restricted to this manifest and its listed `.html` and `.pdf` files. The HTML body carries machine-readable candidate, warning, FPPS and source-projection metadata. The PDF shows the source package, projection and catalog hashes. The generator refuses to replace an existing briefs directory containing an unlisted file.

The five bilingual points are priority status, reporting focus/denominator, one service-specific baseline illustration, the eligible candidate disruption plus verification task, and uncertainty/source time. The illustration is **hospital / walking** only where that variant exists. It is a selected precomputed comparison, not a hospital inventory or route instruction. Hospital, primary care, pharmacy and shelter remain separate; **main-road access** is explicitly unavailable as a separate qualified service result. Road-graph connectivity is not an observed passability or main-road access result. The Public projection sets its generic `access` field to `null`: the source brief's generic legacy vehicle context has a different candidate basis from the finals service/mode variants and must never be presented as the same comparison. All brief numbers come from the selected service/mode variant. Population figures are rounded modelled residents from the package's 2020 WorldPop context, never measured event victims. The reporting coverage fraction refers to study AOI geometry; full-subdistrict totals are not inferred. The lower Chao Phraya briefs explicitly label the shared 2024/2025 static baseline, 10 km AOI routing buffer and AOI-intersection demand/reporting scope. A missing access or disruption value is stated as unavailable, never zero. All briefs say non-operational and `official_warning=false` in English and Thai.

The source analysis creation time is `decision_brief.finals_analysis.generated_at` in the hash-verified EvidenceLibrary package, projected as nullable `source_analysis_generated_at`. The later `package.generated_at` is the **release generation time**. The brief displays both with separate English/Thai labels, and displays source analysis as unavailable when no finals analysis exists. Candidate scene acquisition/source observation time is a third, distinct timestamp. The generator rejects a projected time that differs from the source package, a source analysis later than the release, or a mixed-time release without the source finals receipt and generation-identity hashes.

## Claim limits for presentation

The bound Mae Sai core hospital/walking illustration has approximately 44,160 modelled residents as its service-specific denominator, 15,580 within 30 minutes at baseline, 11,199 losing that threshold under the imposed candidate closure, and 29,642 becoming newly unreachable. These last two outcomes are distinct and must not be added. The closure is an assumption; the candidate scene's post-acquisition time is not the September event peak. A case without an eligible service/mode result states its denominator as unavailable, and a case without an event-bound flood comparison cannot report a zero disruption. Hat Yai core has its own candidate scenario and cannot inherit Mae Sai validation. Lower Chao Phraya year selectors share a static baseline; they are not observed year-on-year flood comparisons. See `CLAIMS.md` and the source catalog for package identities and limitations.

Any new input, wider hosted display, download purpose or accepted decision requires its own source/rights review.
