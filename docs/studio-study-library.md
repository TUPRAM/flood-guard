# Studio study library

Studio separates measured research, model applications, planning qualification and historical experiments. The website displays saved evidence. It does not train models, acquire imagery, or promote research outputs into decisions.

## Pages and ownership

| Route | Evidence owner | Scope |
| --- | --- | --- |
| `/studio/` | Study catalogue | Choose a study; no global model leaderboard or borrowed planning status |
| `/studio/planning-evidence/` | Existing Mae Sai evidence context | Qualification, restricted model registry, governance and authorization |
| `/studio/archive/mae-sai-geoai/` | Historical `2026-07-30-r1` report | Original optical/teacher experiments and earlier research; distillation fidelity is not water accuracy |
| `/studio/studies/c2s-ms-20260915/` | C2S-MS `r1` | Original-chip public benchmark overview |
| `…/data/` | Same C2S revision | All event assignments, observation dates, source licences and geographic context |
| `…/models/` | Selected frozen model/input version | Fitting, features, calibration, abstention and recorded TreeSHAP |
| `…/results/` | Original C2S chips | Raw/calibrated, pooled/per-event, full-valid/selective scores with support |
| `…/rtc/` | Separate matched RTC record | 46 chips, two events, fixed-ramp comparison and transfer limitations |
| `…/explorer/` | C2S human labels and frozen predictions | All 111 test chips; six trained model/input combinations |
| `…/files/` | Source receipts and public projections | Downloadable JSON evidence, attribution, checksums and reproduction limits |
| `…/mae-sai/` | Separate Mae Sai inference record | Six model/input versions, four layers, pre/post radar, checkpoint lineage; no local accuracy metrics |
| `/studio/cases/mae-sai-2024/` | Mae Sai 2024 timeline manifest (`TIMELINE_MANIFEST_URL`) | Hour-by-hour replay of a low-confidence terrain-model reconstruction with dated Sentinel imagery, VIIRS daily flood maps and HII hourly rain; the water is modelled, the VIIRS maps and rain are observed |

Each C2S section has its own static route. Query parameters record model/input, calibration state, event/chip, map layer and overlay selections. Invalid selections or revisions display an unavailable state. Ordinary browser Back and refresh preserve the selection.

## Frozen public projection

`apps/web/public/studies/c2s-ms-20260915/r1/manifest.json` binds the summary and all report/index assets by exact byte length and SHA-256. Its reviewed digest is pinned in `apps/web/src/lib/study-report-release.ts`; the browser does not trust a digest downloaded alongside an unchecked manifest. JSON loads validate study/revision, schemas, safety flags, partition roles, metric support and inference restrictions. Missing, altered, wrongly scoped or redirected evidence fails closed.

The records are independent of `useFloodGuardData` and the existing Mae Sai model registry. No C2S metric is inserted into a blocked Thai evaluation. Separate original-chip, RTC and Mae Sai records retain checkpoint lineage. Source hashes and public-projection hashes are separate because downloads are reserialized and private experiment-root paths are made relative.

The source experiment checkout was `codex/public-flood-models` at `36e2536d9dee68c7747e1755e508893858fd9a69`. Reproduction requires that experiment's archived reports and acquired work data, including its frozen checkpoints. Those large local inputs are not supplied by this frontend branch, and there is no published checkpoint download. The website documents this limit and links public dataset acquisition sources.

### Visual evidence

- All 111 test chips: 65 Australian, 18 Nigerian and 28 Pakistani chips.
- Six combinations: RF, XGBoost and U-Net, each with SAR-only and context inputs.
- 633 combinations with valid inputs; 33 explicitly unavailable combinations from 11 context-empty chips.
- 2,147 small PNG previews, including 26 Mae Sai previews. Full rasters and weights remain outside Git.
- Each available case has radar/reference, calibrated probability, binary prediction and error views. Preview dimensions are at most 256 pixels; benchmark counts use the original full-resolution valid pixels.
- Export verification replayed all 633 available cases from frozen checkpoints. Every TP/FP/FN/TN count matched the archived report exactly. This checks correspondence with the saved C2S evaluation; it does not establish Mae Sai accuracy.
- Mae Sai probability and entropy remain inspectable in abstained areas. The optional tint and separate abstention map disclose the screening result; neither creates a new accepted prediction or reference label.

The visual index itself is checksummed through the manifest. PNGs carry embedded provenance and individual digests in that index. `export_study_visuals.py` verifies all source/checkpoint receipts and the full-resolution confusion counts before publishing a completed index.

`.gitattributes` preserves `/studies/` files byte-for-byte, including the original newline style of independently exported indexes. The integrity check also compares working files with their Git blobs, so a locally passing manifest cannot become invalid after a clean checkout.

### Geographic context

The event map uses the recorded bounding-box centres and Natural Earth 1:110m country outlines. The outlines are [public domain](https://www.naturalearthdata.com/about/terms-of-use/). They are display context, not model features or labels. Country labels inferred by point-in-polygon lookup are marked accordingly; a centre does not describe every chip or establish an event boundary. Source URL, downloaded bytes, SHA-256, verification time and transformation assumptions are saved in `geography.json`.

### Case replay: links, exports and offline copy

The replay's data revision is chosen only by `TIMELINE_MANIFEST_URL` in `apps/web/src/lib/flood-timeline.ts`; the page, the offline inventory (`apps/web/scripts/case-replay-inventory.mjs`), the integrity check and the tests derive every asset from that manifest.

- The page serves revision `r4`, which replaced `r3` (removed from the tree: one revision ships, and an old link to an earlier one no longer resolves). r4 keeps r3's model and figures and adds the evidence fields described below. Since r3 the bake includes the east Copernicus DEM tile (N20E100), so the model covers the whole district (305.6 of 305.6 km²), every road and candidate facility is modelled, and only the four shelter candidates outside the replay grid remain "not modelled"; the impact card then says the district is fully modelled instead of naming unmodelled land. Its HAND raster is RGB: R is the effective HAND code and G the per-cell depth factor k × 255, so depth is k × (stage − HAND) while wetness depends on the code alone. Roads and facilities carry the same k: a road is impassable when the rounded k × (stage − h) reaches 0.3 m and wet when that rounded depth is above 0, the same rule as `floodguard.flood_timeline.road_state`; a Python-generated fixture (`apps/web/scripts/road-state-parity-fixture.py`) checks every hour of the replay grid. The stage is the assumed Sai main-stem stage at the Mae Sai bridges; tributary cells rise k × stage (the page says "a fraction of this level", because k on the page means the plan size). The stage curve interpolates over every anchor, including 10 Sep 18:15 (0.1 m, GISTDA-anchored; GISTDA gives no time zone, so ICT is assumed — as UTC the knot would be 11 Sep 01:15 ICT) and 11 Sep 02:00 (2.5 m). Area, road, facility, people-in-water and access figures recomputed in the browser equal the manifest's baked keyframe statistics, and unit tests enforce this.
- Evidence fields (r4): `timeline.json` follows `packages/contracts/schemas/case-replay-timeline.schema.json`, and the bake refuses to write a manifest that breaks it or the rules in `floodguard.replay_manifest`. Besides the data, the manifest says what the data is: `generated_at`, `data_version`, `dataset_mode` (with `data_mode` kept as an alias), `operational_status` (`non_operational`), `confidence_class` (mirrors `confidence`), `confidence_basis`, `source_name`, `event_time`, `permitted_use` and `reason_blocked`. `accepted_fpps` and `accepted_action_class` are null and `protocol_sha256` is null with the reason `not_a_protocol_case` (D7): the replay computes no score and no action class. `evidence_blocks` gives every part of the manifest a lane, a tier, a temporal relation and its own source timestamp: the water reconstruction, residents in water, access and the shelter plan are `SCN` ("T1 scenario (model)"); the VIIRS maps, each Sentinel-1 and Sentinel-2 image and the rain record are `OBS`; GISTDA's 10 Sep figure, the UNOSAT 3991 size comparison and the 16 Sep Sentinel-1 size comparison are `CAL` (calibration); product 4009 is `SCN-ENV` (a season envelope, not shown); reported shelters and the chronology are `REP`. A test fails when a new block has no lane. `exploratory_knowledge` states which external figures were used or known while the model was tuned: GISTDA's 9.9 km² was used on purpose to set the onset knot; the 16 Sep Sentinel-1 pass was used to re-tune the recession keyframes (best-fit stage 0.10 m); UNOSAT 3991's 70 km² was known during tuning; the VIIRS and product 4009 comparisons were computed after the keyframes were final and were not used. The page's radar line therefore reads "Radar size comparison (Sentinel-1, 6 Sep → 16 Sep 06:16 ICT; calibration-informed, not an independent check)", and nothing on the replay is labelled an independent check. `publication_eligibility` lists a licence and terms per input (HII rain CC BY-NC, OpenStreetMap ODbL 1.0, WorldPop CC BY 4.0, COD-AB CC BY-IGO, VIIRS "No licence stated by the provider", Copernicus DEM and Sentinel under their own terms, and product 4009 CC BY-SA 4.0 marked "Not yet shown; rights record pending owner confirmation"), and `input_sha256` repeats the input receipt's 32 hashes. The top-level `source_timestamp` now spans the dated event observations (Sentinel-2 on 5 Sep to the last rain hour on 19 Sep, which covers VIIRS to 18 Sep), and `source_timestamp_note` says which inputs are dated elsewhere. `sources` names both elevation tiles and WorldPop (the unconstrained `tha_ppp_2020` grid; r3 called it constrained). `generated_at` is a declared bake time (`--generated-at`, recorded in the receipt and carried by later bakes and by `--verify`), or the newest dated input when none was declared; it is never read from the machine clock, so a rebuild gives the same bytes. `git_commit` is null with a reason: a file cannot hold the hash of the commit that adds it, so the receipt identifies the bake sources by SHA-256 and `git log -1 -- <path>` names the commit. On the page, "How to read these numbers" states "Status: non-operational" and when the data files were generated; "Sources, assumptions and limits" adds "Licence per input" with the conditions of use, "What was known when the model was tuned", and the status and generation time in its footer, all in English and Thai. `parseTimelineManifest` reads both the r4 shape and the r3 shape that a client may still hold in its offline copy (a unit test uses a trimmed r3 fixture), fills the defaults r3 implies, and refuses a manifest that claims an official alert, an operational status or an accepted score or class.
- Sentinel-2 scaling (r4): the Earth Search L2A files on disk already have the processing-baseline 04.00 offset removed (in the replay area 75% of the valid red values on 5 Sep and 48% on 15 Sep are below 1000, and red over dense vegetation has a median near 310–320, which would be negative reflectance otherwise), so reflectance is DN / 10000 (`floodguard.flood_timeline.sentinel2_l2a_reflectance`, with a unit test) and the bake no longer subtracts 1000. The display stretch keeps the same cloud cut (DN 3500, now written as reflectance 0.35), so the pictures stay the same: the 15 Sep image is byte-identical to r3, and the 5 Sep image differs in 43 of 13.2 million channel values by one level before encoding (713,848 bytes against 713,912). The other 19 data files are byte-identical to r3; only `timeline.json` grew (196,294 to 221,500 bytes).
- Layout: a short hero (title, one-line lead, the disclaimer and a collapsed "How to read these numbers" box with confidence, timestamps, a link to the assumptions and a glossary of stage, HAND, low-confidence water, road nodes, T1 scenario and freeboard) is followed directly by Play ("Play 9 → 19 Sep (26 s)"), the time readout and a "Map layers" button above the map; their height is reserved from the first render, so nothing that loads later moves the map. Imagery, comparison, water and road modes, water opacity and the layer switches sit in the "Map layers" drawer over the map (Escape closes it). A compact legend for the active water and road modes (and any switched-on scenario or observed layer) sits on the map under the zoom control, with the marker key folded inside it; it starts collapsed on phones. On desktop the map column is sticky beside the cards, so a card's "Show on map", k slider or shelter-set switch changes a map that stays in view; on phones a one-line summary of the moment sits under the readout. Technical terms carry a hover or focus definition from the same glossary.
- Low-confidence water (r3 on): the HAND raster's B channel is 255 on filled pits and dead-flat ground less than 0.1 m above its channel, which reads as wet at almost any stage. The page decodes it only when the manifest declares `hand.low_confidence_channel` ("B"); wet flagged cells are then drawn paler and desaturated with a diagonal hatch in the depth and people views, on the map and in the PNG and video exports, with a legend entry ("Low-confidence water: flat or filled low ground in the elevation model") in both. The evidence card gives the manifest's share (14.0 of the 88.7 km² wet at the modelled peak) and meaning. The figures themselves are unchanged: flagged cells still count as wet.
- Imagery: the 15 Sep Sentinel-2 image is the first clear optical view after the flood; while it is on screen the map, the "This moment" card and the evidence say that its brown areas are mud left by the floodwater (observed). The caption beside the readout always names the image at the playhead (the old fixed "pre-event images" line is gone), and "Hours under water" uses a yellow-green-blue-purple ramp without browns so it never reads as that mud.
- Water can show depth at the moment, the first flooded hour, hours under water, people in flood water (wet cells coloured by WorldPop 2020 residents per hectare) or all residents. Arrival and duration are pure functions of the assumed stage curve sampled at the start of each local hour (9 Sep 00:00 to 19 Sep 23:00); road-cut hours use the same grid and the same 0.3 m threshold as the road state. WorldPop is modelled residential population, not the 2024 population or border-market visitors.
- Evacuation access is a T1 scenario, not observed outcomes. It covers residents at road nodes who can walk to an open, dry shelter within 2 km on roads that are still passable. The shelter set is either the sites reported in use in September 2024 or the first k sites of the ranked plan (k = 1 … N, default the smallest plan that reaches 90% of the most any plan can reach). A population scope says whose access is counted: by default the residents whose home node floods at the modelled peak (the builder's `home_wet` rule on `home_code` at `shelters.method.peak_stage_m`; their sum equals the plan's `demand_people`), or all residents at road nodes. The default compares the reported set and the plan on the people the plan is built for; the card says in one line what the plan optimises (pre-emptive walking coverage of flooded-home residents) and why, counted against all residents, it can look worse than the 2024 shelters. The headline is "Lost walking access because of the flood, at this replay hour"; residents already more than 2 km from a shelter of the set before the flood are grey context, and both together are a smaller line. The node file (`access-nodes.bin`, little-endian columns per the manifest layout) is reduced once per set and scope to cumulative histograms by cut level, so each hour costs O(1). The Evacuation Equity Gap uses the rules of `floodguard.equity`; the page prints the ratio to two decimals with a plain comparison ("Proxy-vulnerable residents are about 3.9× less likely to lose access (4.47% vs 17.56%)"), "— (no one has lost access yet)" when both rates are 0, and one line on why the proxy points the way it does here (hillside and remote homes stay dry). "Vulnerable" there is the terrain/remoteness proxy, not demographic vulnerability. The "people cut off" layer draws the scoped nodes that have lost access as population-weighted blobs on a canvas overlay.
- Shelters: reported 2024 sites are stars with sourced popups and a model check at the modelled peak, and unlocated sites are listed without a pin. The Mae Sai District Office (R05) is drawn as a relief and command site (diamond), not a shelter, and Wat Mueang Daeng (R04) is labelled a shelter only from 21 Sep, following the research notes (`REPORTED_SITE_ROLES`, tied to the manifest wording by a unit test). Plan candidates appear as numbered top-k badges, eligible rings and grey ineligible markers with reasons; candidates off the DEM tile (east of 100°E) or off the grid are drawn as not modelled instead of showing the build's placeholder high-ground or flood results. A collapsible "Other shelter candidates" card lists every ring and dot with its reasons and a "Show on map" button, so none is pointer-only. Popups give the capacity estimate with its Sphere basis and the load for the chosen k. Both plan-size sliders share the label "Plan size k = N" and a sentence that updates with the slider ("k = 3: 3 sites cover 5,725 of 14,169 residents whose homes flood (40%) · late evacuation 23%"); the coverage curve has a y-axis title and shows the ranking as a range, and the uncoverable residents are called out as the shelter gap. Plan sites whose capacity is unknown or less than half of the residents assigned carry a "!" on the map badge and in the list. Plan badges are drawn above the other markers. In English, Thai-only candidate names get an English type label first ("Mosque · มัสยิด…").
- Observed evidence (r3 on): the NOAA/GMU VIIRS 375 m daily flood-water maps (10–18 Sep) can be shown on the map: the pre-coloured PNG of the day at or before the playhead, from its nominal 13:30 ICT pass until the next pass and never past the last mapped date, drawn with pixelated rendering above the model water (VIIRS is purple, the model blue), with a legend (cloud = no observation, flood-water fraction bins, normal open water) and a map note. The "Observed vs modelled (VIIRS, clear sky only)" card tabulates cloud share, clear area, VIIRS flood area and the model's area in the same clear pixels per day, with a one-line reading of each day that states disagreement plainly (for example, no VIIRS flood water in clear pixels where the model places some) and the product caveat; it is a coarse size check, never a validation. HII ThaiWater hourly rain at two gauges is charted under the stage curve on the same time axis (only the playhead moves during playback) and can be shown as gauge markers; it is the forcing, not flooding. Sources list the VIIRS product and the rain record with licence and link, and a reference whose source is now ingested is no longer listed as "not ingested".
- Numbers are qualified where they are counted differently: the people card counts the population grid (81,363 residents in the eight subdistricts) and says that the access and plan cards count the same WorldPop residents snapped to road nodes (81,799, of whom 14,169 have a home node that floods at the peak). The 42 OpenStreetMap facilities are "Key facilities (OSM)" and start hidden (the layer switch keeps them), so "candidate" means only shelter candidates.
- The address bar records `t` (hour index), `img`, `wm`, `wo`, `rm`, `cmp`, `lang`, `layers` (letters `t r f s c i x v g`; `v` the VIIRS map, `g` the rain gauges; the default no longer includes `f`), `set` (`reported` or `plan`), `k` and `pop` (`flooded` or `all`); invalid values fall back to the defaults, and a link without `pop` opens on the flooded-home scope.
- Thai dates show the Buddhist Era year with the CE year in brackets ("ก.ย. 2567 (2024)"), and Thai eyebrows are not letter-spaced. The replay's last position is labelled "end of day (24:00 ICT)" on 19 Sep, not 20 Sep 00:00. Every manifest sentence the page explains in its panels (assumptions, limitations, confidence reasons, set rules and notes, the external checks, the access scenario, the VIIRS and rain notes) has a Thai rendering in `apps/web/src/lib/flood-timeline-copy.ts`, and a unit test fails when a new one lacks it; source names, licences and attributions stay as published, marked `lang="en"`. `plainManifestText` keeps internal ids out of reader copy (`reported_2024`, `tha_ppp_2020`, field names, and decision numbers such as "per decision D3"). The keyboard hint is Thai-only in Thai and hidden on touch screens.
- Map symbols: reported shelters that flood at the modelled peak are pale stars struck through, the relief and command site a diamond, plan sites numbered badges above every other marker; people density uses a yellow-green-blue ramp so red stays for impassable roads. Stars, badges, candidate rings and rain gauges name themselves in a hover tooltip (at least 180 px wide), and popups pan clear of the zoom control and the map notes, which (with the legend) step aside while a popup is open. A selected route gets a cyan halo with a white core, colours no road state uses, and a "Clear route selection" button on the map; showing a shelter clears it. While the imagery swipe is on, the water is drawn at 30% at most and a note says it is the model at the selected hour, not part of either image.
- Wording and caveats: the "This moment" narrative is tagged "Reported:" with its source and compile date, the mud cue "Observed:" and the stage "Model:". Each scenario and model card carries a one-line confidence chip ("CONFIDENCE: LOW · Why, method and source dates") that opens to the reason, method notes and source timestamp; "How to read these numbers" explains the classes once. The longest-cut routes list named roads (English label with the Thai name in brackets, e.g. "Phahonyothin Rd (Hwy 1) (ถนนพหลโยธิน)", "Mae Sai bypass") apart from the top six unnamed street groups, each ranked by road importance (motorway 5, trunk 4, primary 3, secondary 2, tertiary 1.5, other classes 1) × longest cut. Units keep a non-breaking space ("0.3 m").
- Phones: day chips sit in two rows at least 44 px tall, layer switches and the cut-off switch are 44 px rows with 20 px boxes, subdistrict names wrap instead of being cut, and the swipe labels stay clear of the zoom control.
- The floating app-status pill (`PwaRegister`, mounted in the root layout) takes an `autoHidePaths` option; the layout passes `/studio/cases/`, so on the case replay the pill hides itself after four seconds unless it is open, hovered or focused, and has a dismiss button. Every other page keeps the pill unchanged.
- PNG and video exports render offscreen at the full study extent. They draw low-confidence water as the map does and list it in their legend. They carry the model disclaimer, local time, figures (including modelled residents in flood water) with their scope (the modelled part of Mae Sai district, not the whole pictured frame) and source attribution. Frames also show the reported 2024 shelters (same symbols as the map), subdistrict outlines, place labels found from the data (the border bridge at the northern end of Highway 1 over the Sai River, Mae Sai town, and Myanmar (Tachileik) north of the district), a round-number scale bar and a north arrow. Cancelling while the video is still being prepared stops it from starting; a recording started in a hidden tab begins paused. Video is offered only where the browser can record a canvas.
- Offline: the route is part of the competition core cache. Its data (6.1 MB in r4: 6,118,723 bytes with the manifest, including the residents raster, the access node file and the nine small VIIRS maps) is an opt-in bucket, not part of the blocking installation. `verify-study-assets.mjs` fails when the manifest plus the files it lists exceed the 6.5 MB precache budget (6,500,000 bytes, `CASE_REPLAY_BUDGET_BYTES`), when a second revision folder is present, or when the folder holds a file the manifest does not list; the build applies the same budget. Export files for download are measured separately. After the replay renders online, it asks the service worker to keep the manifest's files, and each is stored only when its SHA-256 matches the build. The street basemap is online-only, and the page says so when it is unavailable.
- Confidence and timestamps: the access, plan and reported-shelter cards state the water reconstruction's confidence class, the OpenStreetMap extract date and the WorldPop estimate, and the reported list's status (public reporting, not an official register) with its source-date range. External figures are split into the calibration anchor (GISTDA, which set the onset knot) and calibration-informed size checks (UNOSAT 3991, known while the keyframes were tuned); nothing is labelled an independent check. Since r3 the model's smallest non-zero extent (land within 0.05 m of the channel level, 13.6 km²) already exceeds GISTDA's 9.9 km², so the card says how far the closest stage stays from the anchor and why, computed from the manifest; UNOSAT 3991's cumulative 13–19 Sep extent is compared with the model's largest extent in that window (2.65 m on 13 Sep 00:00 ICT), with the earlier modelled peak shown for reference only. Cards carry planning themes ("Protect Lives Now", "Keep Routes Open"), never FPPS action classes: this replay computes no score.
- Known limits of the r4 build, disclosed on the page rather than fixed in the data: the reported-shelter access set assumes its counted sites are open for the whole replay; the VIIRS comparison covers clear-sky district pixels only and cloud hid at least half of the district on six of the nine VIIRS days, including both peak days (11–12 Sep). The page still drops any listed reference whose URL is the source of an ingested block, so a stale "not yet ingested" note cannot reappear. Low-confidence water is flagged, not removed: its area still counts in the flooded-area, road and people figures.
- Reproducible bake: `python scripts/build_mae_sai_flood_timeline.py --external-root <folder> --verify` bakes the revision again into a temporary folder and compares it byte for byte with the committed `r4` folder (22 of 22 files identical on 1 Oct 2026; 6,118,723 bytes). It never writes to the committed folder and exits non-zero on any difference. Every bake also writes `docs/mae_sai_timeline_r4_input_receipt.json`: the path relative to its root, the size and the SHA-256 of each of the 32 input files the bake opens (about 4.3 GB; all but six files under `outputs/` stay outside Git), the declared `generated_at`, the SHA-256 of the bake's own source files (CRLF read as LF) and library versions. `--verify` reports an input, a bake source or a library that changed since the recorded bake; only the byte comparison decides its exit code. Another GDAL, PROJ, WebP or zlib build can change bytes without changing the method, which is why the receipt records them.
- Access and equity parity: `apps/web/scripts/equity-access-parity-fixture.py` computes with the Python builder and `floodguard.equity` the level index for every replay hour, which resident nodes have lost access, and the Evacuation Equity Gap for four shelter sets, two population scopes and all 81 levels, plus rule cases on both sides of the 1.2 and 0.8 band limits. `flood-timeline-evacuation-parity.test.ts` checks the browser code against that fixture, and `tests/test_equity_access_parity_fixture.py` fails when the fixture is out of date. The figures stay a T1 scenario; "vulnerable" is the terrain/remoteness proxy.
- Wording lint: `apps/web/src/lib/replay-wording-rules.json` lists the banned patterns and the allowed negations for the replay. `replay-wording-lint.test.tsx` applies them to every string in the replay's source files (export captions included), the manifest text and the rendered panels in both languages. `tests/test_replay_wording_lint.py` applies the same file to the manifest, the strings of the three bake scripts, the reported-shelter source file, the input receipt, the parity fixture, this section, the decision log, the product 4009 rights record with its notice, and the standard export header. Both suites must pass on today's text and fail on one seeded bad string per rule. A new negation needs a new entry in the rules file.
- Product 4009 rights record: `docs/proposal_execution/rights_basis_4009_v1.json`, with a licence notice beside it, is a draft until both owners confirm it. Until then `tests/test_rights_basis.py` fails if any file sits in an `unosat4009` folder under `apps/web/public`.

### Historical archive

The archive uses `studies/mae-sai-geoai/2026-07-30-r1/`. It preserves the original report, hashed preview filenames, baseline metrics/notes and MNDWI module diagnosis. The archive wrapper explains the old optical U-Net's teacher-agreement score. The original observation timestamp remains separate from the baseline run date. ## Reproduction and maintenance

From the repository root, with the original experiment data available:

```powershell
# Explicit inputs: an experiment checkout and a separate staging checkout.
python services/geoai-runner/scripts/export_study_visuals.py --source-root <experiment-checkout> --output-root <staging-checkout> --device cuda

# Optional explicit network acquisition for cartographic display only.
# Use the committed r1 summary as the event inventory; output must be new.
python services/geoai-runner/scripts/acquire_study_geography.py --summary apps/web/public/studies/c2s-ms-20260915/r1/summary.json --output <staging-checkout>/apps/web/public/studies/c2s-ms-20260915/r1/geography.json

# Assemble report projections after the visual index and geography exist.
python services/geoai-runner/scripts/export_studio_study.py --experiment-root <experiment-checkout> --output <staging-checkout>/apps/web/public/studies/c2s-ms-20260915/r1

# Validate/reproduce the committed historical projection from its original sources.
node apps/web/scripts/archive-historical-study.mjs
```

The report and historical exporters reject conflicting bytes in an existing revision. Acquisition refuses to overwrite an existing projection. A newly acquired cartographic file has a new verification timestamp; to reproduce the exact r1 bytes, reuse its committed `geography.json`. Future scientific runs require a new study/revision and reviewed manifest pin. Do not update September 15 metrics in place or use the already observed final test for tuning.
